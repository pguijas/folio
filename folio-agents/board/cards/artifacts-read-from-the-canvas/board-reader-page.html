Board reader page

Opening an artifact navigates to a full page the board owns — /kanban/<card>/<artifact> — with board chrome, a reading column, and the card's other artifacts in a rail. Browser Back returns to the board exactly as it was.

What this variant argues

Thesis

An artifact's URL is a board page: opening one is a real navigation to /kanban/<card>/<artifact>, a page in board chrome that Back unwinds perfectly — so card output stops pretending to live in the docs tree.

Back is the board

The dialog and the reader are both history entries. Back from the reader lands on the open dialog; Back again is the canvas, filter and scroll intact. Esc walks the same stairs one step at a time, and switching artifacts in the rail swaps the address in place, so Back never replays your reading.

The compiled /docs page

Retired. This page is what a deep link deserves: the route the build should compile per artifact, owned by /kanban, with no docs sidebar and no seat in the docs tree. /docs/kanban/… becomes a redirect here and nothing else.

What it is bad at

Reading leaves the canvas entirely — no glancing at columns beside the document, which the overlay and rail variants keep. A full navigation is heavy for a ten-second peek at a small file. And for live HTML prototypes the page adds little over "open in a new tab": an iframe inside chrome is still a frame.
