# Internationalization (i18n)

Folio supports multi-language documentation sites. i18n is opt-in -- if you don't configure it, your site works in single-language mode as before.

<Callout type="warning" title="Experimental feature">
  Internationalized docs are disabled in this release while the routing surface stabilizes. These notes are kept for future work and are not included in generated public docs.
</Callout>

## Configuration

Add an `i18n` section to your `docs.yaml`:

```yaml
project:
  name: "MyProject"

source:
  python:
    paths:
      - "src/"
  docs:
    - "docs/"

i18n:
  default_locale: "en"
  locales:
    - code: "en"
      name: "English"
    - code: "es"
      name: "Español"
    - code: "fr"
      name: "Français"
```

- **`default_locale`** -- The locale code used when no locale prefix is in the URL.
- **`locales`** -- A list of supported locales, each with a `code` (used in URLs and file paths) and a `name` (human-readable label).

## Directory Structure

Organize your documentation files by locale. Place translated content under locale-prefixed directories inside your docs source:

```
docs/
  en/
    index.md
    getting-started.md
    api-reference.md
  es/
    index.md
    getting-started.md
    api-reference.md
```

The default locale's content is served at the root path (`/docs/getting-started`), while other locales are served under their prefix (`/es/docs/getting-started`).

## How It Works

When `i18n` is configured in `docs.yaml`, Folio injects the locale configuration into the Next.js config at build time. Nextra handles the routing and locale switching automatically.

If no `i18n` section is present, the site runs in single-language mode with no changes to behavior.
