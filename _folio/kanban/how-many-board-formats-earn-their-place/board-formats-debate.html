How many board formats earn their place

Three ways to declare a board, one of them operable. Four adversarial seats argued the count from repository evidence; the judge's call, the matrix, and each seat's best three punches are below. The decision lands on the card, not here.

The judge
Retire source: board.yaml; keep inline and cardfile.
Its only documented growth path leads out of itself, every board that verifiably exists is a cardfile, and the replacement is a four-line fail-loud error that links the migration recipe which already exists as an error target.
  1. Retire the board file
  2. Cardfile only
  3. Keep all three

The four seats, three punches each

Seat 01

Keep all three: stopping points on one ramp, not three products.

  • The comparison table gives each format an honest, distinct job (formats.md:12-16).
  • Total extra code is ~40 lines on a shared pipeline, and every failure is loud and names the resolved path.
  • Deleting shipped surface turns working configurations into build failures, for tidiness.
Concedes — every observed board is cardfile; the ramp has no demonstrated traveler.
Seat 02

Retire the board file: the middle format's promise refutes itself.

  • "A larger board, still one file" describes exactly the board that wants cards, and the CLI refuses it with exit 1 (cli.md:27).
  • Not zero-friction (already an extra file) and not operable: no user segment left to serve.
  • Its documentation already contains the instructions for leaving it, linked from a live error (formats.md:68-78).
Concedes — a deliberate breaking change to delete ~20 lines and ~30 tests, with zero known users affected either way.
Seat 03

Cardfile only: one idea, one format, every card a file with real history.

  • The read-only formats dilute the pitch and split the export button into two meanings.
  • Every docs page pays the which-format caveat; every reader carries the matrix in their head.
  • The demo job could be served by a tiny scaffolded cardfile instead of a second format.
Concedes — it kills the ten-line taste, the cheapest zero-command first render an evaluator gets.
Seat 04 · no side taken

The segments map: count users before counting formats.

  • Docs-page owner wanting a static status board: inline. Team or agents operating work: cardfile.
  • No verifiable segment picks the board file; every observed board is cardfile.
  • ~34 of 154 kanban tests serve the legacy formats and their coexistence — standing cost the other seats hand-wave.
Concedes — the inline segment is itself unobserved: docs examples only, no board in the wild.

What each decision costs

Retire the board fileOne loud breaking change: the loader branch becomes a four-line error, five tests go, formats.md, cli.md, index.md and the drifted FAQ (why-folio.md:127) get edited together. Known blast radius: zero.
Keep all threeNo breakage now; the matrix is paid forever — the three-row table, the two-meaning export button, the per-page caveats, the ~34 coexistence tests, and a FAQ already drifted wrong.
Cardfile onlyEverything above plus breaking inline's documented job and forcing the init apparatus (directory, template, SKILL.md, branch) on boards that only display.
